# 验证记录

## 开发版 · 从当前 PDF 开始阅读

- 在 Windows 的 Chrome 和 Edge 中，用工具栏按钮打开 1,073 页投资学教材。转到 PDF 第 971 页，切为仿生模式、缩放到 200%，再横向和纵向滚动。关闭阅读页，从原标签页重开后，页码、缩放和两个方向的滚动位置逐项相同。
- 用包含 Transformer 论文原文的测试站点模拟登录。地址没有 `.pdf` 后缀，须携带测试会话才能取得文件。扩展读出了下载文件名和 15 页正文，按 `#page=6` 打开。普通 HTML 即使以 `.pdf` 结尾也回到文件选择器。另在 Chrome 验证了登录失效、关闭「允许访问文件网址」两种情况，均能按提示手动打开。
- 从 PDF 的链接注释独立读取目标网址和矩形，在 Chrome 和 Firefox 以 200% 缩放实点《Attention Is All You Need》第 10 页的代码库和 RFC 9110 第 170 页的 DOI。原始、仿生两种模式均打开新标签页，关闭后原页码、缩放及滚动位置一致。另在 Chrome 实际联网，代码库返回 HTTP 200，DOI 返回 302 并跳至 IEEE Xplore。[论文](https://arxiv.org/abs/1706.03762) · [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)
- 浏览器回归还检查了「适合宽度」下在较窄窗口重新打开时的段落位置、旧版页码进度的迁移，以及网页链接打开后无法访问来源窗口。自动化链接测试使用固定响应以便复现。

## 0.4.3 · 2026-11-08

- 在 200% 缩放下，分别用原始和仿生模式点击 5 个链接。教材包含第 12→469 页的跳转和第 12→418 页的指定矩形区域，论文第 2→11 页定位到靠下的参考文献，RFC 第 34 页在同页内跳转。逐次核对视口，后退和再次前进均恢复原页码、缩放及横纵滚动位置。
- 用 PDFium 独立提取所查单词的页码和字形坐标，再在 Chrome 中逐处向前、向后查找。教材 `Treynor` 共 82 处，Transformer 论文 `sinusoid` 共 4 处，双页 PLOS 讲义 `probability` 共 26 处。教材第 971、980 页的制表符标题另在 100% 和 200% 缩放、原始和仿生两种模式下逐项检查高亮边界。
- 把 6 页 PLOS 论文拼为 3 张双页讲义，导出普通版和可切换版。逐页比较文字和左右两半的像素，关闭图层时与原件逐像素一致。另用含扫描页、空白页的 6 页混合讲义验证，界面和命令行均列出未加粗的第 2、6 页。

在 Windows Chrome 中，先从各文件的链接注释独立读出目标物理页，再点击页面上的对应位置。原始模式使用适合宽度，仿生模式使用 125% 缩放。

教材 17 个页面上的 1,218 个书内链接全部生成了点击区域。PDF.js 读出的链接矩形和目标页与 pypdf 对同一原件的结果逐条一致。按同一方法还核对了 Transformer 论文的 95 个和 RFC 9110 的 3,211 个书内链接。下表列出实际点击的样本范围。

| 测试文档 | 实际抽查 |

在最终 Chrome 包中，教材抽查的 6 个页面首次以原始模式显示时均只绘制一次，同页同缩放恢复原始模式时复用之前的画面。带邮箱、等号、网址的三个独立样本在浏览器和桌面端分别强调 18、15、13 个字形。受限文档在两种模式下都会拦截真实的复制快捷键。

## 0.4.2 · 2026-11-08

- Chrome、Edge 和 Firefox 验证了清空页码、恢复旧配置和损坏进度、切换语言及规则时的词首预览。选页导出拒绝无效页码，保留有效页码的顺序与重复页。

- 对同一份正文逐一选择自动模式和 13 种语言，检查导出副本的语言标记、词首画面和原文。自动模式还用一份 1,073 页文档整本回归，生成的可切换副本与上次修复后的文件逐字节一致。
- 用相同字号和正文测试异常 CID 字宽范围。将范围末端从 199,999 增到 2,147,483,647 后，加粗字形数和生成的页面绘图指令一致。

## 0.4.0

测试日期：2026-11-06。所有可公开测试均使用原创短句和 OFL 字体，没有教材或用户文档进入仓库、发布包或 CI。

### 已通过的本地测试

- Python：31 项通过，包含 13 种语言、分解重音、分片单词、连字、Identity-H、已有图层、空白页、原文与像素对比。
- JavaScript：17 项通过，包含与 Python 共享的词首用例、ActualText 连字、多栏复制顺序，以及 Safari 文字流的读取、取消和错误处理。
- Chrome 156.0.8078.80、Edge 156.0.4314.58、Firefox 153.0：每个浏览器验证 13 页基础样例，以及 13 种语言 × 带标签 / 不带标签两种打印 PDF；检查可选择文字、复制顺序、模式切换和原始像素恢复，没有外部文件请求。
- Chrome 独立扩展：实际加载 Manifest V3 包，检查 CSP、模块 worker、文件选择与模式切换。
- WPS 12.1.0.29161：之前已人工检查长文档图层开关、页码、缩放、正文和批注原位保留。
- PDF-XChange Editor 11.1.1.0：已在原生程序人工检查图层面板、默认关闭和开关、页面及缩放保留。13 种语言的完整页面回归在自动化引擎中进行，没有冒充每页原生界面人工验收。

### 发布前的跨平台检查

GitHub Actions 运行 Windows / Ubuntu 上 Python 3.11、3.13 的测试与构建、Chromium / Firefox 浏览器、Windows 独立程序转换，以及 macOS 的 Apple PDFKit、Safari。发布只使用通过验收的构建产物；具体运行链接在发布说明中记录。

本次 [完整验收运行](https://github.com/Yanxxzz/bionic-pdf-reader/actions/runs/42217027961) 的 7 个任务全部通过。Windows 包验证了 13 种语言转换、独立 GUI、完整语言列表、使用指南和内置网页资源；6 个发布包另做 SHA256、许可证、指南及归档内容检查。

Apple PDFKit 实际检查 13 页的原始文字、图层关闭时原始像素、普通仿生输出的加粗。Preview 也完成了打开文件及进程启动检查，这不等于逐页人工界面验收。

真实 macOS Safari 26.6.2 完成 13 种语言 × 带标签 / 不带标签两种 PDF，共 26 个案例，检查原始文字、词首加粗、选择复制和关闭恢复。控件通过 DOM 激活，并检查控件在屏幕上的实际命中位置；没有用 Playwright WebKit 冒充 Safari。

Safari 的系统文件选择和原生鼠标点击不列为通过项：SafariDriver 在不含阅读器代码的独立文件输入框上，使用 arrayBuffer 和 FileReader 均报 NotReadableError。本次渲染验收因此使用包含相同 PDF 字节的内存 File，环境记录和每个案例都注明输入方式。这验证真实 Safari 的阅读引擎与 DOM 控件，不替代系统文件对话框或原生点击验收。源码保留探针和结果记录，不隐藏此限制。

尚未将 Acrobat、Foxit、SumatraPDF 或手机应用列为本次逐应用实机验收；它们通过标准图层或普通 PDF 方式适配，见 [compatibility.md](compatibility.md)。

这些测试验证显示和文字保留，不是阅读速度或理解率实验。字体和编码边界见 [languages.md](languages.md)。
